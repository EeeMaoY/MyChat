## 3. 关键设计约定（S9）

1. **OPK 池（服务端组装）**：`PreKeyBundle` wire 结构不变（协议规范 §4 不升版）；节点 `GET /v0/registry/bundle/:did` 从该用户池中挑一个未消耗 OPK 组装返回，**返回即标记已发**；响应方 accept 成功后 `DELETE .../opk/:opkId` 确认消耗（未确认的由客户端对账时回收）。池空时 bundle 无 OPK 字段——v0.2 协议规范将标注 opkOptional（core X3DH 的 DH4 可选支持排期 S9 末评估，先以"池水位告警"退化）。
2. **会话替换语义**：Double Ratchet 会话与 (contact, 创建时间) 绑定；新握手 accept 成功即替换，旧会话丢弃（消息历史不动）。替换事件上抛 UI（对齐设计报告 §10.3"联系人设备变更轻提示"）。
3. **包裹 v2**：`{ v:2, identity, myName }`；恢复导入后自动 `setUsername` 尝试重注册原用户名（被占用则提示）。
4. **cursor 分类**：解密/解析失败 → cursor 照常推进（安全丢弃，SR-4 语义）；kv 写入失败 → 不推进（下轮重试）。空拉取仅更新内存。

## 4. S9 验收 Gate

1. 恢复后（原数据已清）与旧联系人**重新握手即可双向通信**（KI-1/KI-4 闭环，浏览器 e2e）。
2. 同一联系人连续两次"更换设备"（重握手）后，双方会话均可用且消息历史保留。
3. 恢复完成后用户名自动回填（或明确提示占用），托管副本引导出现（KI-2）。
4. 长时间运行 cursor 键数量与活跃信箱数同阶（KI-3）。
5. 恢复演练：一键完成本地完整性检查并给出可理解报告（UX-2）。
6. 回归：M0/M1 全部既有测试保持绿色。
