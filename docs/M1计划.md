## 3. 关键设计约定（S5 即时生效）

1. **消息结构化**：会话明文统一为 JSON `{ v:1, type, ... }`（type: `chat` / `image` / `file` / `receipt`）；传输层 wire 格式不变（协议规范 §7 不升版）。
2. **回执语义**：单勾=已投递节点信箱（现状）；双勾=对端已拉取（delivered receipt）；蓝色双勾=对端已读（read receipt）。回执本身是 E2EE 会话消息，**已读回执关闭时不发送任何 read receipt**（FR-5.2 无可分析差异）。
3. **附件加密**：随机 CK（XChaCha20-Poly1305）加密文件 → `CID=BLAKE3(密文)` 入 CAS；CK 放入 E2EE 消息体。节点只见密文块（SR-1 不变）。
4. **托管副本最小形态**（M1）：备份块直接入公共 CAS（CID 即能力）；加密备份清单（块 CID 列表 + 块密钥包裹）经信箱发给 2 位托管好友——好友不可读、互不知晓对方也是托管者。完整擦除编码分片为 M2。

## 4. M1 验收 Gate

1. **回执**：单/双/蓝勾三态正确；关闭已读回执后会话无 read receipt 消息产生。
2. **富媒体**：图片经节点全链路密文（隐私门测试扩展覆盖附件路径）；接收端完整还原。
3. **导出**：导出包在新浏览器环境（空 IndexedDB）完整恢复身份/联系人/会话/消息。
4. **托管**：清除本机数据后，凭好友托管的加密副本恢复全部数据；托管好友视角无明文。
5. **社交恢复**：模拟设备丢失，3/5 守护者完成恢复；守护者不可见账号内容；原设备可否决；恢复演练一键可用。
6. **KT**：客户端可验证包含性/一致性证明；映射篡改可被核验发现。
7. **回归**：M0 全部 88 项测试保持绿色；新增模块测试覆盖密码学与编排路径。

## 5. 风险登记（M1 增量）

| # | 风险 | 缓解 |
| --- | --- | --- |

## 11. M1 验收结论与已知问题（v1.1 增补）

**浏览器 e2e 全旅程**（三隔离环境 alice/bob/carol，真实 dev-node）：注册互加 → 文本/图片消息端到端（解密渲染 ✓）→ 守护者设置（公告+分片分发，双侧持有验证 ✓）→ 模拟设备丢失 → 恢复向导（公告验证→添加守护者→广播请求→守护者横幅人工确认→分片收集）→ **身份密钥级恢复**（恢复出的 IK 与原身份一致）→ 恢复后身份可重新发起社交。Node 侧 Gate e2e（附件隐私门 + 恢复全流程）全绿。
