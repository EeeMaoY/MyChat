## 1. 范围约束（用户决策）

- **单节点自足运行是长期使用形态**：本里程碑全部改动不得破坏单节点的独立运行、部署与维护。
- **多节点与多副本交叉核验降为评估保留项**：KT 一致性验证武器已备（core 前缀一致性 + `/v0/kt/leaves`），待出现真实多副本需求再立项；协议接口（ADR-11 四接口分离）保持不变，未来引入多节点不动客户端协议面。
- 协议规范不升版：本里程碑全部为节点运维与客户端体验层改动。

## 3. S13 关键设计

1. **限流语义**：资源治理而非鉴权——按**信箱伪地址**限速（防定向灌垃圾，不看身份）、按**节点全局**限块/注册（防资源耗尽）。超出返回 429，参数可经启动选项注入（默认值见实现）。
2. **快照与轮转**：启动重放后若 JSONL 记录数超阈值（默认 20000），把当前内存态**反推**为等效记录序列写入 `snapshot.json` 并轮转日志——重放逻辑复用（快照 = 记录集），单一事实形态。已知边界：手动 `POST /v0/kt/append` 的事件不进快照（自动锚定的 register/device 事件随记录重建）。
3. **部署指引**：数据目录即备份单元；TLS 由反代终结（Caddy 示例）；systemd 守护示例；限流参数说明。

## 4. S13 验收 Gate

1. 限流：超速信箱 append 与注册返回 429；正常速率不受影响；参数可注入（测试小值验证）。
2. 快照：超过阈值后重启——数据完好（registry/信箱/块/KT 根链延续）且 JSONL 重置为增量；阈值内行为不变。
3. 纯内存模式（未设 MYCHAT_DATA_DIR）行为完全不变。
4. 回归：全部既有测试保持绿色。
