## 3. S11 关键设计约定

1. **群标识与群信箱**：`groupId = base58(random 32B)`（不绑定创建者 DID）；群信箱 `groupMailboxId = HKDF(groupSecret, epoch, "mailbox")` **随 epoch 轮换**——被移除者连新信箱都不可达（Level0 断读的物理面）。节点只见一个轮换的伪地址信箱（群活跃度可被观察，与 1:1 同级如实披露）。
2. **群状态（GroupState）**：`{v:1, groupId, name, owner, members:[{did, role}], epoch}`，群主 IK 签名，经群信箱广播 + 1:1 会话同步；成员本地镜像权威清单，群主签名验证后才采信。
3. **Sender-Keys**：epoch 内每发送方一个链密钥 SK（32B），组内消息 = 哈希链推进（KDF_CK 同构）+ XChaCha + **发送方 IK 签名**（FR-6.2 防伪造）；成员缓存各发送方链头。SK 集经各成员 **1:1 DR 会话**分发（移除者拿不到新 epoch 的 SK 集 = 断读的密码面）。
4. **成员变更**：owner 签发新 GroupState（epoch+1）→ 全部 SK 重生成重分发（线性开销，N≤50 可接受，评估报告 §6 如实登记）；v1 支持 owner 移除任意成员、成员自愿退群。
5. **服务域零改动**：群消息就是普通信封投群信箱；大附件走既有 CAS 块 + CID 进组内密文。信箱配额 1000 条（开发节点属性）。
6. **诚实边界**（UI 与协议文档同步披露）：组内前向保密依赖 epoch 重分发频率，弱于 MLS 树结构；群信箱活跃度对节点可见；被移除者对已缓存历史副本的读取不可物理追溯。

## 4. S11 验收 Gate

1. 建群（3 人）→ 多发送方群聊，各成员均可解密并验证签名。
2. 移除成员 → epoch+1 → 被移除者**无法解密新消息**（群信箱与 SK 双面失效）、**无法伪造**（IK 验签拒绝）。
3. 新成员加入 → 仅见加入后的消息（history: new-only 默认）。
4. 附件经群聊全链路（CAS + 组内 CK）可达。
5. 回归：M0/M1/M2 全部既有测试保持绿色。

### 5.2 Gate 验收（Node e2e 全过；全仓 152 项测试绿：core 126 + dev-node 26）

1. ✅ 建群 → 密钥经 1:1 分发 → 三方多发送方群聊全员可解、署名正确。
2. ✅ 移除成员 → epoch+1 → 被移除者旧视角解不开新消息（信箱+密钥双面失效）、伪造消息被拒。
3. ✅ 新成员加入 → 仅见加入后消息；新 SK 下各发送方 index 空间独立无冲突。
4. ✅ 群附件全链路（CAS 块 + 组内 CK）可达。
5. ✅ 回归全绿。

### 5.3 过程记录与边界

- 组内消息密钥采用**每消息独立派生**（HKDF(SK, groupId:epoch:sender:index)）而非哈希链：消除失步问题（个别丢帧不阻断后续消费），组内前向保密由 epoch 轮换承担——Sender-Keys 边界，评估报告 §6 如实登记。
- KT 一致性以**前缀一致性**落地（语义等价 RFC 6962）：pad-to-2^k 树形态与 RFC 6962 left-aligned 不同，标准证明需迁移树结构（协议 v0.2 评估）；安全语义相同（可检测分叉/篡改），开销 O(n) 与客户端事件流折叠同阶。
- UI 边界：v1 成员管理仅群主移除 + 邀请；成员自退群、群主转让、群名修改排 S12 后评估。

## 6. S12 关键设计约定（动态 v1，EDS-min）

1. **好友圈密钥（momentKey）**：32B 随机对称密钥，仅作者与好友持有；经 1:1 DR 会话分发（type:"circle-keys"，与 group-keys 同构；加好友后与启动补发时投递）。v1 不轮换（泄露 = 好友圈历史暴露；"重置好友圈"为 P2），如实披露。
2. **动态信箱 = 动态日志**：`momentFeedId = HKDF(momentKey, "moments-feed-v1")`（无 epoch）；条目 `{v:1, type:"post"|"delete", cid, contentKey, nonce, at}` 以 momentKey AEAD 加密后 append——好友按 cursor 增量拉取即时间线发现。单信箱 1000 条配额（开发节点属性），超限报错，信箱治理后续。
3. **动态内容块**：每条动态独立内容密钥（`encryptAttachment` 模式）——文字与图片引用一起入块（图片本体另为独立 CAS 块，与 1:1 附件对称）；块 CID 经日志条目分发，任何知道 (cid, CK) 的好友可取回解密。
4. **删除（FR-4.4）**：作者 append 墓碑条目（type:"delete"）+ 调用节点 `DELETE /v0/storage/blocks/:cid`（物理增强，新增端点）。好友端以墓碑为准隐藏动态；新读者拉日志见墓碑即不呈现；**已缓存的密文副本无法物理强制删除**——需求文档固有边界，UI 如实告知。
5. **互动（FR-4.3 v1 子集）**：仅评论，经评论者→作者的 1:1 会话投递（type:"moment-comment"），**仅作者可见**（好友圈共享评论为 P2），UI 明确标注。
6. **时间线（FR-4.2）**：本地聚合——对每个持有其 momentKey 的联系人拉动态日志增量（cursor 复用信箱治理），按时间归并、本地缓存离线可刷；无算法推荐（Non-Goals）。
7. **节点改动**：仅新增 `DELETE /v0/storage/blocks/:cid`（CAS 无归属的物理删除；cid 不可枚举，攻击者需已知 cid——与既有读者集合基本重合，DoS 面如实登记）。

### 6.1 S12 验收 Gate

1. 互为好友双方：一方发布文字动态，另一方时间线可见可读。
2. 图片动态全链路（动态块 + 图片 CAS 块，两层独立密钥）可达。
3. 删除：墓碑传播后对方 UI 隐藏 + 块物理删除（新读者 getBlock 404）。
4. 新加好友：拿到 momentKey 后只见现存动态，已删动态不可见。
5. 评论：好友留言经 1:1 会话到达作者并挂载（仅作者可见语义）。
6. 回归：M0/M1/M2/M3-S11 全部既有测试保持绿色。

| 2 | **好友申请缺"通过"动作**（FR-8.1 简化遗留）：陌生人握手直接成为联系人 | 好友确认流：陌生人握手照常完成密码学处理（accept + OPK 消耗）后进入**待确认队列**（不入联系人）；通过 = 会话转正 + 分发好友圈密钥；拒绝 = 静默丢弃（对方无感知可重申请）；已知好友的重握手替换语义（S9）不变。UI 顶部申请横幅（通过/拒绝） |

## 9. 安全加固批次（v1.5 增补，2026-11-07）

| # | 项 | 交付 |
| --- | --- | --- |
| ① | **W1 密钥存储保护**（路线图头号安全债） | scrypt（N=2^15,r=8,p=1）派生 KEK → IndexedDB 全部私钥/会话/群组/动态材料 AEAD 包裹（"默认加密、白名单明文"）；锁屏解锁、修改口令（全量重加密迁移）、15 分钟无操作自动锁定；未设置口令保持"无感创建"UX 并常驻引导；**忘记口令不可解密**（备份导入恢复），UI 如实披露 |
| ② | 动态日志条目 IK 签名 | 条目带作者 IK 签名（确定性编码域），读取强制验签——圈密钥持有者伪造他人条目在签名层被拒；e2e/单测锁定冒名与篡改场景 |
| ③ | 好友圈密钥重置 | "我的"页一键重置：换发新圈密钥全量重发，旧密钥（含泄露情形）无法解密新日志；好友端经 DR 会话认证接受换钥（重放被 DR 拒绝） |
| ④ | KT 完整性自动核验 | 启动静默核验 + 恢复演练并入检查项：我名下全部 KT 事件逐条索取 Merkle 包含性证明本地验签；边界如实登记（单节点核验不防整体重造，多副本交叉核验为 M4） |

**登记边界**：口令强度由用户负责；加密对抗"拷库/他人使用设备"，不对抗运行中的恶意代码；消息文本 `msg:*` 本批次一并加密（本地泄露面最小化）。
