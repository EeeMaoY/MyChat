# MyChat 单节点部署指引

> 适用形态：一台服务器运行单体 dev-node（Relay / Storage / Registry / KTLog 四角色同进程，ADR-11）。
> 节点只搬运密文、不裁决身份；本文所有措施均为**资源治理与可用性**配置，不改变协议语义。

## 1. 启动与环境变量

```bash
# 仓库根目录
npm install && npm run build -w @mychat/core

# 基本启动（纯内存，重启即空——仅演示用）
npm start -w @mychat/dev-node

# 生产建议：启用持久化
MYCHAT_DATA_DIR=/var/lib/mychat MYCHAT_PORT=8629 npm start -w @mychat/dev-node
```

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `MYCHAT_PORT` | 8629 | 监听端口 |
| `MYCHAT_HOST` | 127.0.0.1 | 监听地址；对外服务改为 0.0.0.0（务必配合反代 TLS） |
| `MYCHAT_DATA_DIR` | 未设置 | 持久化目录；设置后变更追加 JSONL、重启重放恢复 |

## 2. 持久化与备份

- 数据目录三个文件：`node-log.jsonl`（增量日志）、`snapshot.json`（压缩快照，记录数超 2 万时自动生成）、`node-log.jsonl.*.bak`（轮转保留一代）。
- **备份 = 拷贝整个数据目录**（建议停机拷贝或定期 `cp -r`）；恢复 = 放回目录后重启。
- 长期运行无需手动维护：JSONL 达到阈值会在下次启动自动压缩（内存态反推为快照，重放逻辑复用）。

## 3. TLS 与反向代理（Caddy 示例）

节点本身只做 HTTP/WS；公网部署**必须**由反代终结 TLS：

```caddy
# Caddyfile
chat.example.com {
    reverse_proxy 127.0.0.1:8629
}
```

Nginx 等价配置需同时转发 `/v0/relay/subscribe` 的 WebSocket 升级（`proxy_set_header Upgrade/Connection`）。

## 4. 进程守护（systemd 示例）

```ini
# /etc/systemd/system/mychat-node.service
[Unit]
Description=MyChat dev-node
After=network.target

[Service]
WorkingDirectory=/opt/MyChat
Environment=MYCHAT_DATA_DIR=/var/lib/mychat
Environment=MYCHAT_PORT=8629
Environment=MYCHAT_HOST=127.0.0.1
ExecStart=/usr/bin/npm start -w @mychat/dev-node
Restart=always
User=mychat

[Install]
WantedBy=multi-user.target
```

## 5. 限流与资源配额

默认参数（代码内 `DEFAULT_LIMITS`，可经启动选项注入调优）：

| 参数 | 默认 | 语义 |
| --- | --- | --- |
| 信箱 append | 120 条/分钟/信箱 | 防定向灌垃圾（按伪地址限速，不看身份） |
| 块 PUT | 600 次/分钟/节点 | 防资源耗尽（附件/动态/托管共用） |
| 块总量 | 20000 块/节点 | 存储护栏，超出返回 429 |
| 注册 | 60 次/分钟/节点 | 防脚本批量注册 |

超限一律 HTTP 429。限流为内存态滑动窗口，重启即清零。

## 6. 如实边界

- 单点部署：节点不可用期间消息不可投递（客户端缓存本地重试）；这是开发/小规模部署形态的已知属性。
- KT 手动事件（`POST /v0/kt/append`）不进快照，压缩后丢失；自动锚定的 register/device 事件随快照完整保留。
- OPK"已分发未消耗"集合不持久化：重启后一次性分发语义短暂退化（既有已知边界）。
- 节点不作鉴权裁决（零信任语义）：公网部署请依赖反代侧的访问控制策略（如需）。
